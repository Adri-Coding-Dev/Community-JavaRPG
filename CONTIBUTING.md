# 📌 Reglas Importantes

## 1. Prioriza simplicidad

No sobreingenierices.

Preferimos:

* código legible,
* modular,
* mantenible.

---

## 2. Mantén coherencia arquitectónica

Aunque algo funcione,
puede rechazarse si:

* rompe arquitectura,
* introduce complejidad innecesaria,
* dificulta mantenimiento.

---

## 3. Evita Pull Requests gigantes

Haz PR:

* pequeños,
* claros,
* específicos.

---

## 4. Respeta la estructura actual

No:

* renombres sistemas críticos,
* reorganices carpetas arbitrariamente,
* rediseñes arquitectura sin discusión.

---

# 🌱 Principiantes Bienvenidos

Este repositorio también es educativo.

No importa tu nivel.

Si tienes dudas:

* pregunta,
* abre discusiones,
* crea Draft PR,
* participa.

```txt

```

---

# 🚫 Prácticas Prohibidas

Evita:

❌ Clases gigantes

❌ Herencia excesiva

❌ Código duplicado

❌ Variables globales innecesarias

❌ Abstracciones absurdas

❌ Código imposible de leer

---

# ❤️ Filosofía Final

El objetivo no es escribir:

> el código más inteligente.

El objetivo es escribir:

> el código más mantenible y entendible posible
